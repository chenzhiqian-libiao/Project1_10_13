## 角速度换算（重要）

`xv7001bb.h` 的 `XV7001BB_SCALE_16BIT` 取 **`70.0f`**，即 **70 LSB/(°/s)**。

手册标称 16 bit 输出是 280 LSB/(°/s)，但本器件实测只有 70：转台精确转 90°，
按 280 换算积分只得到 22.5°（正好差 4 倍），按 70 换算后 90°/180°/360° 的读数
与真实角度一致。原因可能是器件的 16 bit 字为“14 bit 数据左对齐”（低 2 位恒 0）。

早期固件为抵消这 4 倍，把积分系数 `GYRO_ANGLE_SCALE_CALIBRATION` 设成 `4.0f`；
现在驱动直接按 70 换算，4 倍已撤销，该系数只留作角度标度细调。

### 标度细调（`GYRO_ANGLE_SCALE_CALIBRATION`）

角度积分还差一个**恒定的标度误差**，用 CSV 里的 `motor_angle_deg` 列当真值标定出来的。
2026-10-20 两个数据文件共 **28 段 180° 行程**，模型 `M = s·G + c`（M = 电机角，无噪真值），
最小化 `Σ(sG+c−M)²`：

```text
s = 1.00633 ± 0.00087   (7.2σ)      c = −0.042° ≈ 0
```

- 即陀螺**恒定读小 0.63%**：正转读小、反转也读小，28 段符号无一例外 → 纯标度误差。
- 截距 `−0.042°` ≈ 0，没有固定偏置，所以只需一个乘性系数。
- 效果：180° 行程的系统性少算 **1.15° → 去程残余 −0.003°、回程 +0.003°**。

> **标定只能用"干净"的行程。** 同一文件里 6 段**连发**的 90° 行程（间隙 0.33 s，
> 小于 `GYRO_ZUPT_CONFIRM_SAMPLES` 的 0.5 s 确认窗口，ZUPT 全程未重锁）多背了约
> 0.4° 的自由积分零偏，其 `G/M = 0.9825` 明显低于 180° 段的 `0.9937`；把它们混进去
> 会把标度估成 `1.0069`（偏大 0.06%）。以后重标定请确保**每段运动前留 ≥ 2 s 静止**。

> `GYRO_ANGLE_SCALE_CALIBRATION` **不会**改善 180° 往返残差。无论是标度误差还是
> 每次运动的固定损失，在去程/回程里都同号出现，相减时正好抵消；往返残差（σ≈1.4°）
> 来自残余零偏（σ≈0.39 °/s），它在往返里**同向相加**，改这个常数动不了它。
> 往返误差是纯随机的（均值 +0.08°），逐次不累积，要更准就多跑几个往返取平均
> （σ → 1.4/√N）。

> 更换器件或更换量程档位后必须重新标定这个常数，否则**所有以 °/s 为单位的阈值**都会失真。

## 信号处理链

```text
SPI 原始码 ──/70──► measuredRateDps
                        │
                        ├─ 减 bias ──► correctedRateDps
                        │
                        ├─ ZUPT 静止判定（滞回：入场中值 + 出场原值）
                        │      ├─ 稳态静止 ──► 静止零偏块平均（更新 bias）
                        │      │                角度按 0 速率保持，不积分
                        │      │                零偏每变一点，按解析式平滑补进角度
                        │      ├─ 运动结束 0→1 ──► 挂起上一段，开始积累新静止均值
                        │      └─ 运动开始 1→0 ──► 精确重放上一段（补完余量）+ 起点前滚
                        │
                        ├─ 3 点中值 + 一阶低通（≈5 Hz）
                        └─ 梯形积分（稳态静止时不积分）──► 累计角度
```

| `GYRO_RETRO_PREROLL_SAMPLES` | 25 | 运动起点前 0.25 s 的前滚样本，用于补起步坡道 |
| `GYRO_RETRO_MIN_SAMPLES` | 10 | 少于 10 拍的运动段不回溯 |
| `GYRO_RETRO_BIAS_RAMP` | 0.5 | 重放零偏过渡：0=整段用新零偏，1=整段线性过渡 |
| `GYRO_RETRO_BIAS_WEIGHT` | 0.75 | 由 RAMP 导出：`1 − RAMP/2`，零偏误差换算成角度误差的系数 |
| `GYRO_RETRO_CREEP_SLEW_DPS` | 1.5 | 静止期间平滑修正的速率上限（°/s），0=不限速 |
| `GYRO_RETRO_CREEP_MAX_SAMPLES` | 250 | 平滑修正只跟到第 250 个静止样本（≈2.5 s）就冻结目标零偏 |
| `GYRO_ANGLE_SCALE_CALIBRATION` | 1.0063 | 标度细调，按实测角度残差标定（见上文「标度细调」） |

### 读取失败不丢积分时间

`XV7001bb_ReadAngle()` 失败（SPI 出错，或码值超出物理范围被判 `dataValid = 0`）
时，旧实现会把 `havePreviousRate` 清 0，于是恢复后的那一拍 `elapsedMs = 0`，
**读失败前后整整两个周期（20 ms）的角度被整段丢掉**。114.6 °/s 匀速时一次掉拍
就少算 `2.3°`，几次就足够把 180° 积成 178°，而且看起来像"标度不对"。

现在掉拍只记 `gyroErrCount`，积分状态原样保留，下一个有效样本按真实
`elapsedMs` 把空洞一起积进去（梯形积分天然处理跨接）。只有空洞超过
`GYRO_MAX_BRIDGE_MS`（50 ms）才把积分 / ZUPT / 滤波状态整体作废重来，
避免拿一个陈旧角速度乘一个很大的 `dt`。副作用是一次孤立掉拍也不会再打断
0.5 s 的静止确认窗口。

### 校准零偏抗尖峰

零偏是 200 拍的算术平均，对孤立尖峰毫无抵抗力：实测出现过单拍 2865 码
≈ 40.9 °/s 的 SPI 损坏样本，一个就够把均值拉偏 `40.9 / 200 ≈ 0.20 °/s`
（折成角度是每 2 s 行程少算 0.4°），而且还会把峰峰值判据顶穿、把干净的一轮
误判成"校准降级"。现在累加前先过 3 拍中值，孤立尖峰被完全剔除，
代价只有 2 拍（20 ms）延迟。

### 静止判据的滞回（ZUPT）

入场和出场必须用不同的信号，否则总有一头吃亏：

| 方案 | 抗单拍尖峰 | 退出延迟 | 结果 |
|---|---|---|---|
| 只用中值 | 是 | 晚 1 拍 | 200 °/s 快转启动丢 `0.01 s × 200 = 2°` |
| 只用原值 | 否 | 0 | bit10 位错（14.6 °/s）打断 0.5 s 确认窗口 |
| **滞回（当前）** | **是** | **0** | 两边的损失都消掉 |

- **入场**：`|3 拍中值| <= 40 °/s` 连续 50 拍 → 锁定。
- **出场 tier-1**：单拍 `|原值| > 80 °/s` → 立刻解锁（0 拍丢失）。
  80 °/s 取在入场门限的 2 倍：实测单拍尖峰已到 `gyroDbgJudgePeakHoldDps = 40.93 °/s`
  （≈2865 码，不是真实角振动），必须让 tier-1 明显高于入场门限，
  否则 40~80 这一档全被 tier-2 的两拍确认吃掉。
- **出场 tier-2**：连续 2 拍 `|原值| > 40 °/s` → 解锁（丢 1 拍即 10 ms，
  在 40~80 °/s 区间最多 0.8°，且起步坡道补偿会收回）。

> ★ 门限沿革：`3.0`（驱动小 4 倍的旧读数）→ `12`（换算到真实 °/s）→ `20` →
> **`40`（2026-10-21，按现场"静止仍掉锁"再抬）**。抬门限是治标：40 °/s 相当于
> 台架上 35 mm/s 以下的匀速运动会被判成静止、不计入角度。要根治得消掉那类
> ~40 °/s 的单拍尖峰（降低 SPI 时钟、加重试，或让入场判据改吃滤波值）。

> **死区由出场这一侧决定。** 锁定期间只有 tier-2 能松开，所以“比门限慢的
> 持续转动会不会被冻结”看的是 tier-2；入场门限只影响“停下之后多久重锁”。
> 两者目前共用 `GYRO_ZUPT_MAX_RATE_DPS`，所以取的是两者的较大值。

> **下限约束来自出场信号。** 入场吃 3 拍中值，噪声底可以压得很低；出场吃
> 未经中值的 10 ms 原值，噪声底高得多。按 2026-10-20 实测的尾部分布，出场
> 2 连击的误解锁率：6.5 → ≈0 次/小时、5.0 → 0.02 次/小时、4.0 → 1 次/小时、
> 3.5 → 7 次/小时。所以 6.5 已接近这套判据的可行下限，再往下必须先给出场
> 也加中值。

### 门限的实测标定（`GYRO_ZUPT_MAX_RATE_DPS`）

门限不能靠“比峰值大一点”来定：`gyroDbgJudgePeakHoldDps` 是 `√(2·ln N)` 意义
上的极值统计量，拿它当门限会过度保守。正确做法是用
`gyroDbgHistOver[] / gyroDbgHistSamples` 算出各候选门限的单拍超限率 `p`，
再按 50 连击模型换算成“打不断确认窗口”的概率。

2026-10-20 实测（严格静止 5 分钟，`gyroDbgHistSamples = 30648`）：

| 指标 | 数值 |
|---|---|
| `gyroDbgJudgePeakHoldDps`（判据信号峰值） | 4.13 °/s |
| `gyroDbgHistOver` | `{2404, 52, 0, 0, 0, 0}`（>2 / >4 / >8 / >12 / >20 / >32） |
| `gyroDbgHoldRunMax` / `SlowExitCount` / `FastExitCount` | 50 / 0 / 0 |
| `gyroAngleDriftDps` / `gyroDbgZuptLostDeg` | 0.00 °/s / 1.76°（5 分钟累计） |

用 `>2` 与 `>4` 两点拟合指数尾 `p(T) = p(4)·exp(-(T-4)/0.52)`，它预测 `>8`
有 0.02 拍、实测 0 —— 尾部模型可用。据此外推：

| 门限 | 5 分钟内原始超限拍数 | 出场 2 连击误解锁 / 小时 |
|---|---|---|
| 5.5 | 2.9 | 0.003 |
| 6.0 | 1.1 | 0.0005 |
| **6.5（当前）** | **0.43** | **≈0** |
| 7.0 | 0.17 | 0 |
| 9.0（旧值） | 0.004 | 0 |

`gyroDbgZuptLostDeg = 1.76°` 折合残余 **0.0058 °/s ≈ 21 °/小时**，即“没有 ZUPT
时会漂多少”，可直接当作 ZUPT 的收益指标。

> 复测注意：`*Hold`、`gyroDbgHistOver[]`、`gyroDbgHistSamples` **只在上电时
> 清零**，中途动一下板子，峰值就永久停在那一拍的读数上。每次都要在校准完成、
> 偏置收敛约 10 s 后在 Watch 里手动写 0，再开始计时。

### 静止零偏估计与运动段回溯修正

#### 为什么旧算法改不动往返残差

旧算法只有“向前”的零偏慢跟踪：静止时让 `bias` 慢慢靠近当前残余，运动时
`bias` 冻结。于是**运动段内**的零偏误差没有任何机会被修正——远端停 2 s 后
即使测出了新零偏，去程那 1.8 s 已经按旧零偏积完了，只能从回程开始生效。
陀螺的零偏又确实会随温度/时间缓慢变化，所以“去程 178°、回程回到 179°”这类
**同向残差**会一直存在，靠改 `GYRO_ANGLE_SCALE_CALIBRATION` 也压不掉。

新算法把“已经积错的那段”重新算一遍：

1. **运动开始（ZUPT 1→0）**：开始把每一拍的原始码和 `dt` 存进
   `gyroRetroRaw[] / gyroRetroDtMs[]`，同时把段起点角度、零偏和滤波器状态
   一起记下来。
2. **起点前滚**：缓冲区前面额外放入运动开始前最后 0.25 s 的静止样本
   （`GYRO_RETRO_PREROLL_SAMPLES = 25`）。这段时间在旧算法里被冻结，但平台
   其实已经在加速；重放时把它按真实角速度积进去，起步坡道 0→门限就不再丢。
   前滚的前 3 拍 `dt = 0`，只用来给 3 点中值环建初值，避免拿单个噪声样本
   当种子。
3. **运动结束（ZUPT 0→1）**：锁定拍也算运动段的最后一拍（它是减速尾巴），
   追加完再停。然后用**锁定之后**的静止样本重新估计零偏：
   `bias = (旧零偏 × W + Σ原始样本) / (W + N)`，`W = 20`，`N` 最多 500。
   锁定拍本身不进均值——它可能还带着减速尾巴。
4. **精确重放（起转前那一次）**：把整段原始数据按
   `bias(s) = startBias + (newBias - startBias) × (1 - RAMP + RAMP × s/count)`
   重新补偿、中值、低通、梯形积分，得到新的段增量，再用
   `段起点角度 + 新段增量` **替换**累计角度。`RAMP` 默认 0.5：
   - `0`：整段都用新零偏，适合“零偏在段内基本不变、只是起点估计偏了”；
   - `1`：整段线性过渡，适合“零偏在段内均匀漂移”；
   - `0.5`：折中。离线仿真里对“随机残余零偏”和“线性温漂”两种场景的总误差最小。
5. **静止期间平滑修正**：零偏估计每拍都在更新，上一段运动的正确角度也跟着
   变，但**不能**“每隔 0.25 s 整段重放一次”——那会让静止角度一格一格地跳
   （台阶高度 = 零偏估计噪声 × 段时长，实测可达 1.3°；`PRIOR_WEIGHT` 只改变
   台阶分布，改不掉台阶本身）。这里改用解析式连续补：
   ```text
   ∂(重放增量)/∂(目标零偏) = −段时长 × (1 − RAMP/2)
   每拍：角度 += −Δ零偏 × 段时长 × 0.75
   ```
   再按 `GYRO_RETRO_CREEP_SLEW_DPS`（默认 1.5 °/s）限速，把锁定后头几拍最快的
   那段零偏变化摊成 0.3~0.5 s 的平滑滑动。
6. **2.5 s 后冻结目标零偏**（`GYRO_RETRO_CREEP_MAX_SAMPLES = 250`）。块平均
   本身会一直微动（超过 500 拍转 τ=5 s 慢跟踪），若角度一直跟着走，长时间
   静止就会看到角度缓慢游走——仿真 30 s 静止可达 0.94°。冻结后角度彻底不动，
   起转前的精确重放也用同一个冻结值，所以不会“最后再跳一下”。代价是停
   30 s 相比用最新估计少收约 0.1°。
7. **起转前的精确重放**：把还没滑完的残差一次补上（此时平台已经在动，
   看不出来），然后才开始新段。
   所以远端停 ≥1 s 后上一段的角度就基本收敛了；停 2 s 和停 10 s 得到的往返
   残差几乎一样（除非零偏在这段时间里真的变了）。

#### 为什么静止角度不再跳

| 做法 | 静止期间每拍最大角度变化（仿真，200 次） | 30 s 长静止的游走 |
|---|---|---|
| 每 250 ms 整段重放（旧） | **1.27°**（台阶） | 0（但停 2 s 后就不再修正） |
| 解析式连续补，不限速 | 0.26°（头几拍仍是小台阶） | **0.94°（一直在爬）** |
| 解析式连续补 + 1.5 °/s 限速 + 2.5 s 冻结（当前） | **0.015°**（＝1.5 °/s × 10 ms） | **0** |

0.015°/拍 相当于 1.5 °/s 的匀速滑动，肉眼是“数值慢慢走到位”，不是跳变。
整段修正量典型 0.1~0.6°，也就是 0.1~0.4 s 走完，之后完全静止。
把 `GYRO_RETRO_CREEP_SLEW_DPS` 调到 0 会退回“每拍补满”，头几拍仍看得出台阶；
把 `GYRO_RETRO_CREEP_MAX_SAMPLES` 调大（或去掉冻结）会让长时间静止时角度
跟着零偏估计的噪声慢慢游走。

#### 静止时角度怎么动

稳态静止的判据是 `zuptWasActive && zuptActive`：上一拍和这一拍都确认静止。
这时角度**不积分**（零速率约束），同时每拍仍用静止样本更新 `bias`。锁定拍
和起转拍不满足这个条件，所以它们仍然积分——这两拍正是减速/加速坡道的尾巴，
不能丢。于是静止期间角度只有两种动作：

| 来源 | 幅度 | 形态 |
|---|---|---|
| 零速率约束（不积分） | 0 | —— |
| 平滑修正（零偏估计收敛） | 0.1~0.6° | 1.5 °/s 匀速滑动，0.1~0.4 s 走完，然后彻底停住 |

也就是说：静止时不会再“自己往前漂”，但锁定后的最初约 0.5 s 里会看到数值
匀速走到正确值，之后一直保持不变（目标零偏在 2.5 s 冻结，见上一节）。
`gyroAngleDriftDps` 在这 0.5 s 内会显示 1.5 °/s 左右，那是修正速率，不是
漂移；0.5 s 后它应回到 0.00 °/s。

- `gyroZuptStaticSamples` 是稳态静止拍数，`gyroStaticBiasSampleCount` 是本段
  参与零偏平均的样本数。两者都应在远端停顿时持续增长。

> 这里的“静止稳定”指**静止时角度不再随时间漂移**，不是保证往返后一定
> 回到 0.00000°。往返后的残余由静止零偏估计误差决定（σ≈1.9/√N °/s × 运动
> 时间），仿真里 0.4 °/s 残余 + σ=1.9 °/s 噪声约 0.9° RMS。要显示严格的
> 0.00000 只能在主机侧做“静止归零”（会掩盖真实误差），或者加长静止时间、
> 换低噪声器件。

#### 静止零偏估计的细节

- **只用 `|补偿后角速度| <= 3 °/s` 的样本**（`GYRO_STATIC_BIAS_MAX_RATE_DPS`）。
  ZUPT 门限是 6.5 °/s，起转/停转的坡道尾巴可能还挂在锁定状态里，rate 有几
  °/s；混进均值会把零偏带偏。3 °/s 只挡坡道尾巴，正常静止噪声（σ≈1.9）绝大
  部分仍保留。
- **用原始样本求和，不用补偿后的样本**：如果用 `measured - bias` 求和，零偏
  越修越接近 0，和也跟着变小，会形成负反馈，估计值永远到不了真值。
- **旧零偏权重 `W = 20`**：校准后的残余零偏是“旧信息”，新静止段是“新信息”。
  W 太大会跟不上零偏变化，太小会被静止噪声带跑。20 拍等效权重 + 1.5 s 静止
  段（150 拍）时，新测量占 88%。
- **噪声极限**：静止噪声 σ≈1.9 °/s，150 拍平均后约 0.155 °/s；乘 1.8 s 运动
  时间约 0.28°。这是单段零偏估计的物理下限，靠算法本身消不掉；要再小只能
  延长静止时间、降低传感器噪声，或在主机侧做多圈平均。

#### 调试观察量

| 变量 | 含义 |
|---|---|
| `gyroRetroCorrectionCount` | 精确重放次数（现在每段只有起转前一次） |
| `gyroRetroCorrectionDeg` | 最近一次精确重放把角度改了多少（°，有符号） |
| `gyroRetroCorrectionTotalDeg` | 精确重放修正量绝对值累计（°，手动写 0 清零） |
| `gyroRetroCreepDeg` | 静止期间平滑修正累计滑动的角度（°，每段锁定后清 0） |
| `gyroRetroBiasDps` | 最近一次精确重放使用的新静止零偏（°/s） |
| `gyroRetroSegmentSamples` | 最近一次重放覆盖的样本数（含起点前滚） |
| `gyroRetroOverflowCount` | 缓冲装不下或单拍 `dt>255 ms` 的次数（该段不做回溯） |
| `gyroRetroInvalidCount` | 读失败/时序不连续导致放弃回溯的次数 |
| `gyroStaticBiasSampleCount` | 本段静止已参与平均的样本数 |
| `gyroBiasEstimateDeltaDps` | 当前零偏相对上电校准零偏的变化量 |
| `gyroZuptStaticSamples` | 稳态静止拍数（累计） |

一轮 180° 往返、远端停 2 s，正常应看到：

- 远端锁定后立刻开始平滑修正：`gyroAngleDriftDps` 显示约 1.5 °/s，
  持续 0.1~0.4 s，然后回到 0.00 °/s；
- `gyroRetroCreepDeg` 累计到 0.1~0.6°（就是这一段滑掉的角度）；
- `gyroRetroBiasDps` 从校准值向远端实测值靠拢，`gyroBiasEstimateDeltaDps`
  同步变化；
- 再起转时 `gyroRetroCorrectionCount` +1，`gyroRetroCorrectionDeg` 通常
  只剩几十毫度（平滑修正已经把大部分滑完了）。

如果 `gyroRetroCorrectionCount` 一直是 0：

- 远端停顿不足 0.5 s，ZUPT 没重锁；或
- 运动段短于 `GYRO_RETRO_MIN_SAMPLES`（10 拍 = 0.1 s）；或
- `gyroRetroOverflowCount` 在增长（运动段超过 5.12 s，现为 512 拍缓冲，
  约 360° 以上；需要加大缓冲，同时注意 C8T6 的 20 KB RAM）；或
- `gyroRetroInvalidCount` 在增长（SPI 读失败导致段作废，先查硬件）。

#### 修正时机与读数建议

静止角度在锁定后 0.1~0.4 s 内匀速滑到正确值，之后完全不动。所以：

- **不要去读刚锁定那一瞬间的角度**，等 `gyroAngleDriftDps` 回到 0.00 °/s
  再读（约 0.5 s）；
- 做标度标定（`motor_angle_deg` 拟合）时，等远端停顿 ≥1 s、修正滑完后再
  记录角度，否则会把“还没滑完的角度”混进标定样本；
- 若上位机图形仍嫌 1.5 °/s 太陡，把 `GYRO_RETRO_CREEP_SLEW_DPS` 调小
  （例如 0.5，0.5° 需要 1 s 滑完），代价是短停顿（<1 s）时修正滑不完，
  残差会留到起转前那次精确重放里一起补。

#### 离线仿真结果

用与固件逐行对应的 C# 模型（10 ms 采样、同样的中值/低通/ZUPT/前滚/重放/
平滑修正）跑 180° 往返 + 2 s 远端停顿，静止噪声 σ=1.9 °/s，200 次随机种子：

| 场景 | 无回溯（对照） | 每 250 ms 整段重放（旧） | 平滑修正（当前） |
|---|---|---|---|
| 残余零偏 0.4 °/s，无噪声 | 1.24° | 0.50° | **0.49°** |
| 残余零偏 0.4 °/s，σ=1.9 | 1.50° RMS | 0.93° RMS | **0.88° RMS** |
| 零偏线性漂移 0.2 °/s²，σ=1.9 | 2.12° RMS | 0.67° RMS | **0.69° RMS** |
| 理想无零偏，无噪声 | 0.11° | 0.15° | **0.15°** |
| **静止期间最大单拍角度变化** | 0 | **1.27°（跳）** | **0.015°（滑）** |

平滑修正与整段重放精度相当（差异在仿真噪声里），但静止期间不再有台阶：

```text
discrete(500ms/250ms)  mean +0.6714  rms 0.9328  max static step 1.2709 deg
smooth-creep           mean +0.6315  rms 0.8818  max static step 0.0150 deg
```

**为什么 `PRIOR_WEIGHT` 调不到“不跳”**：它只改变零偏估计的收敛速度，台阶
来自“整段重放→替换角度”这个离散动作。W 越大，估计越慢、台阶越多、每级
越小但总位移不变；W 越小，头一级台阶越大。台阶高度 ≈ 估计噪声 σ/√N × 段
时长，与 W 无单调关系。要消掉它只能改动作本身（本版的解析式连续补）。

> 仿真只建模零偏，不含标度误差、安装偏置和实际运动轨迹误差。如果改完
> 回溯后往返仍是 178°/179°，先按 360° 整圈重新标
> `GYRO_ANGLE_SCALE_CALIBRATION`，不要把标度残差当成零偏继续压。

## 应用层 CAN 协议

所有多字节载荷字段采用小端序，有符号整数，以实际源码为准。

| 标准 ID | DLC | 载荷 |
|---|---|---|
| `0x321` | 8 | D0–D3：int32 累计角度 × 100000（°）；D4–D5：int16 温度 × 100（℃）；D6：状态位；D7：采样间隔（ms，最大 255） |
| `0x323` | 4 | D0–D3：int32 滤波后角速度 × 100000（°/s） |
| `0x324` | 8 | D0–D1：int16 原始 SPI 码；D2–D5：uint32 采样时刻（HAL tick，ms）；D6–D7：int16 零偏 × 1000（°/s） |
| `0x325` | 8 | D0–D3：int32 滤波后角速度 × 100000（°/s）；D4–D7：uint32 采样时刻（ms），与 0x324 相同 |
| `0x322` | 1 | `01`：请求重新零偏校准；`02`：请求角度清零 |

`0x321` 的 D6：

| bit | 含义 |
|---|---|
| 0 | 角度/采样有效（含校准完成条件） |
| 1 | 温度有效 |
| 2 | 校准完成 |
| 3 | 校准失败（会自动重试） |
| 4 | 零漂抑制判定为静止（角度已锁定） |
| 5 | 校准为降级模式（峰峰值超限但均值可用） |

数据每 10 ms 上传一帧（0x321/0x323/0x324/0x325 严格同源，来自同一次临界区快照），
温度约每 1 s 读取。重新校准时应保持板子静止。上位机直接解析板端角度，不做额外比例修正。

`0x324`/`0x325` 是**离线分析用的原始采样帧**，只在 `task_gyro` 产生新样本时发送：

- `gyroSampleSequence` 每成功读到一个样本 +1，`task_can_tx` 只有看到序号变化才发这两帧；
  读取失败或 SPI 超时的周期**不发**，避免把上一拍的旧值重复记成新样本。
- `0x324` 的 D2–D5 是**读完 SPI 那一刻**的 `HAL_GetTick()`（不是任务唤醒时刻），
  用它算相邻样本的 `dt` 才能反映真实采样间隔。
- `0x324` 的 D6–D7 是当前零偏（含校准均值与静止慢跟踪），
  `raw_code / 70 - bias` 就是进入中值 + 低通之前的去零偏角速度。
- `0x325` 重复 0x323 的滤波值，但带上同一个时间戳，上位机据此把两帧配成一条记录；
  时间戳对不上（0x324 丢失）时整条记录丢弃，不会把两拍的数据拼在一起。
- `gyroRawCode` / `gyroSampleTickMs` / `gyroSampleSequence` / `gyroBiasDps` /
  `gyroRateFilteredDps` 也可以在 VisualGDB 的 Watch 窗口直接看，不接 CAN 也能查。
- 发送计数：`gyroCanTxRawOkCount` / `gyroCanTxRawErrCount` 只统计这两帧，
  `gyroCanTxOkCount` / `gyroCanTxErrCount` 是四帧合计。

> 上报周期由 `CAN_TX_PERIOD_MS` 决定。2026-10-20 由 100 ms 改为 10 ms：
> 积分本来就在 100 Hz 跑，10 Hz 上报会把加速/减速坡道压成 1~2 个点，
> 起动与停止丢掉的那 0.2~0.5° 在曲线上看不出来。1 Mbps 下四帧/10 ms ≈ 42 kbit/s，占用可忽略。
